# Proposal: 补差价系统（add-price-diff-payment-system）

## Why

公司为 to-C 业务模式，用户购买服务后常因升级、变更服务内容需要补一笔差价。当前流程是客服手动让用户私下转账：收款无凭证、金额无校验、进度无跟踪，财务无法对账，存在资损与合规风险。需要一个规范的补差价收款系统：运营建单 → 生成 H5 支付页与短链 → 客服转发 → 用户在线支付 → 全流程可视化对账。

项目定位（已与需求方对齐）：**可演示完整链路，核心资金链路（幂等/状态机/对账）按生产标准设计，外围功能简化**。支付渠道一期使用 Mock（内置模拟收银台），但支付流程结构完整，真实微信/支付宝渠道可插拔接入。

## What Changes

全新项目（greenfield），不修改任何现有系统：

- **新建后端工程**：Java 17 + Spring Boot 3 单体，Maven，MyBatis-Plus，领域分包（order / payment / link / admin / dashboard）
- **新建前端工程**：Vue3 + Vite，含三个页面：后台管理端、H5 支付页、模拟收银台（模拟第三方支付 UI）
- **运营后台**：账号登录（JWT）、基于原订单创建补差价单（必填：原订单号、商品名称、补差金额；选填：原订单金额、原商品名称、名额说明、备注、有效期）、订单列表与详情（支持按原订单号归集查询）、支付情况跟踪
- **短链服务**：订单创建后生成不可猜测的随机短码短链，H5 匿名访问，有效期跟随订单
- **H5 支付闭环**：用户打开短链查看订单 → 发起支付 → 跳转模拟收银台 → 模拟第三方异步回调 → 订单状态流转；支持模拟支付成功/失败，失败后可重新发起支付
- **资金安全设计**：回调幂等三道防线（验签 + 外部交易号唯一约束 + 状态机前置校验）；订单默认 48h 有效期，定时任务关单 + 回调惰性校验双保险；金额一律服务端下发，前端不参与金额传参
- **数据模型**：补差价单（diff_order，必填原订单号引用关联，同一原订单允许多笔补差价）与支付流水（payment_txn）分表，一笔订单可多次发起支付
- **仪表盘**：收款总额、订单数、支付成功率、趋势图等整体数据
- **明确 non-goal**：退款、支付后履约触发（下游权益变更）、真实渠道对接、多实例部署（数据模型均预留扩展）

## Capabilities

### New Capabilities

- `admin-auth`: 后台账号登录鉴权。账号密码登录签发 JWT，接口鉴权与角色区分（运营/管理员），未登录访问被拒绝。
- `diff-order-management`: 补差价单管理。运营基于原订单创建补差价单（必填原订单号、商品名称、金额；选填原订单金额、原商品名称、名额说明、有效期），订单列表/详情查询（支持按原订单号归集），订单状态机（待支付/已支付/已关闭），超时未支付订单自动关闭（定时任务 + 回调惰性校验双保险），运营可手动关闭未支付订单。
- `short-link-access`: 短链生成与访问。为订单生成 SecureRandom 8 位 Base62 短码短链，短码不可猜测不可遍历；通过短码换取订单脱敏信息，过期/关闭订单短链失效。
- `h5-payment`: H5 支付页交互。用户凭短链查看订单信息（金额服务端下发），发起支付获取收银台跳转地址，支付完成后查看支付结果；支付失败可重新发起。
- `mock-payment-channel`: 模拟支付渠道与回调闭环。PaymentGateway 接口抽象 + MockGateway 实现；模拟收银台页面模拟第三方 UI 与"成功/失败"按钮；回调端点验签、幂等处理（重复回调只成功一次）、流水状态流转、成功后回写订单。
- `payment-dashboard`: 数据看板。收款总额、订单统计（总数/待支付/已支付/已关闭）、支付成功率、近 N 日收款趋势；订单列表分页筛选。

### Modified Capabilities

（无 —— 全新项目，无现有能力）

## Non-goals

以下内容本期明确不做（数据模型预留扩展点，留待后续变更）：

1. 退款（含部分退款、原路退回）
2. 支付成功后的履约触发（下游权益/服务变更通知）
3. 真实支付渠道对接（证书管理、对账文件下载、渠道对账单核对）
4. 多实例高可用部署、分布式锁、消息队列
5. 细粒度 RBAC 权限体系与多租户
6. 原订单存在性校验（原订单系统不在本项目范围，仅引用式登记，留对接扩展点）

## Impact

- **代码**：新增两个工程目录 —— `backend/`（Spring Boot 单体，Maven）、`frontend/`（Vue3/Vite）；无现有代码受影响
- **API**：全新 REST API —— 后台管理 API（JWT 保护）、开放 API（短链换订单信息、发起支付）、支付回调端点（模拟渠道调用）
- **依赖**：Spring Boot 3.x、MyBatis-Plus、JJWT、H2（默认）/ PostgreSQL（profile）、Vue3、Vite、ECharts（仪表盘图表）
- **数据**：新建表 `admin_user`、`diff_order`、`payment_txn`；无数据迁移
- **外部系统**：无真实外部依赖；模拟收银台在系统内闭环；真实支付渠道对接留待后续变更
